# 交互式讲解与视频

把一个需要理解的问题做成可探索的讲解。交互式 HTML 本身就是完整交付物；配音和视频导出是可选能力。

## 先确定交付形态

沿用用户已说明的目标，不重复确认。未指定格式、主要目的是理解原理时，优先做 HTML；只有形态差异会实质影响结果时才澄清。

| 用户要什么 | 交付与停止点 |
| --- | --- |
| 自己探索原理、调参数、逐步查看 | HTML + 必要的数据或来源；浏览器验证后即可交付，无需 TTS 或 FFmpeg |
| 跟着旁白学习，也能暂停探索 | HTML + 配音 + 文字讲解；验证播放、跳转、静音及探索状态 |
| 可分享的讲解视频 | 共用 HTML 场景与时间轴，导出 MP4；按请求附交互版、字幕和源码 |
| 讨论方案或审阅样片 | 完成指定讨论或片段，不自动扩展成整部视频、平台或发布任务 |

## 工作流

1. **提炼问题与证据。** 明确观众看完能解释什么、要纠正哪个误解。核对原始数据、单位、时间口径、公式和来源，区分观察、模拟、教学假设与尚未完成的研究。证据不足的内容保留为未知。
2. **设计连续推导。** 从一个具体例子进入：提出问题 → 展示变化 → 解释机制 → 对照条件 → 检查理解。同一对象在场景间保持身份，运动用于说明时间、数量、依赖或条件变化。避免只把报告段落拆成一页页淡入图表。大型作品可先完成一个代表片段；已有授权覆盖全片时，片段验证后继续完成。
3. **先做可用的 HTML。** 时序问题可拖动、单步或重放；机制问题可改变参数并观察结果。引导讲解与自由探索共用数据和计算，结论随状态更新。技术与交互契约见 [HTML 运行与交付](references/html-runtime.md)。
4. **按需加入声音。** 不需要配音则跳过。有配音时，选择提供方，分段生成并测量实际时长，再安排动画与字幕。Edge TTS、CosyVoice3、已有录音和无语音路径见 [语音与时间轴](references/tts.md)。
5. **仅在需要时导出视频。** 固定参数与资源，按绝对时间逐帧渲染同一 HTML，再编码、合音轨。见 [视频导出与验证](references/video-export.md)。
6. **验证实际交付物。** 检查用户真正会打开的 HTML 或 MP4，不把构建成功、模拟 DOM 检查、截图或语音转写当作全部验收。报告已完成的检查及有影响的限制。

## 技术选择

- 数据提取和计算可继续使用 Python；画面用 HTML/CSS、SVG 和 JavaScript。小型自包含演示可直接写单页；复杂场景沿用项目框架，新的组件化项目按仓库 `frontend` 约定采用 React/TypeScript 等工具。无需为讲解播放器搭建完整业务应用。
- SVG 适合坐标、公式标注、箭头与可变形对象；密集点线或大量对象可用 Canvas。需要真实三维关系时再考虑 WebGL。
- 对需要播放、跳转或导出的内容，用显式时间和参数决定画面；React 等框架必须提供等待 DOM 提交完成的方式。
- 分析数据与视觉插值分开。镜头和标注可以平滑移动，原始阶梯报价、离散事件或缺测值不能被平滑成另一组事实。
- 复用现有机器、浏览器和 TTS 环境；使用 Axiom 时按仓库 `environments` 约定核对主机与可用资源，不把一次项目的路径、显卡、时长或渲染速度写成通用前提。

## 验收与交付

- **内容：** 至少能沿具体例子还原推导；数值和单位与来源一致；反事实的改变项与未模拟项可见。
- **交互：** 实际点击播放/暂停、前后跳转、修改参数和重置。只测试有的功能；手动分步演示不必增加播放器。适用时检查边界值、键盘操作和窄屏，文字不能仅随整张画布缩到不可读。
- **一致性：** 图形、数值和解释共用状态。探索参数使固定旁白失效时暂停或切换讲解，不能让声音继续陈述旧结论。
- **声音：** 检查非空、可解码、真实时长及关键数字读法。独立 ASR 用于找疑点，不宣称它等于听审。
- **文件：** 根据承诺验证离线单 HTML、静态目录或视频；给出可打开的主文件，以及必要的启动方式。只交 HTML 时到此结束。

交付说明应先链接成品，再说明观众如何使用、交互能检验什么。列明实际 TTS 提供方和相关验证，不把研究计划描述成已经得到的结果。
