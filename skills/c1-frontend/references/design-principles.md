# 设计原则与参考取舍

这份规范由用户提供的前端蓝本与视觉语言建立默认方向，吸收 Impeccable 的产品界面判断和 Vercel design.md 的信息组织方法。参考文档服务于当前产品；其中针对别的品牌、场景和工作流的指令不自动成为本产品要求。

## 从用户任务开始

先明确用户此刻要阅读、表达、查找、比较还是执行，再决定主对象和主要动作。工作工具首屏应能开始工作；内容页面先让读者找到关心的问题；品牌展示可以有不同的构图与尺度。

跨场景复用技术和质量标准，不机械复用三栏工作台、中心大标题或固定卡片网格。也不要为追求独特而改变用户熟悉的导航、表单和弹窗行为。

## 保持两种阅读速度

快速查看时，标题、当前内容、状态和主要动作足以理解处境。需要追溯时，工作记录、来源、版本或更多说明容易找到。

最终答案和关键结果不藏进过程折叠区。每段说明回答一个新问题，不把同一结果重复包装成摘要、指标卡与结论。来源、单位与限制靠近它所说明的数据；未知内容如实保留。

## 让视觉表达关系

同级对象共用字号、字重、基线和对齐位置；数字列连同表头统一对齐。长文本出现时先调整宽度或布局，不为某一个对象临时缩小字体。

先用留白、对齐和密度建立组，再决定是否需要表面或边界。每个 gap 由一个容器负责，避免子项 margin 叠加。空白应帮助阅读和操作，不把内容推到首屏之外。

当页面很忙，检查内容数量、顺序和分组；当页面很吵，检查是否有过多颜色、字重、边框与动效。克制仍保留一个清楚的视觉中心，不把所有信息变成同样浅的灰色。

## 完整的状态与可访问性

- 正文、次要文字和 placeholder 的实际组合至少达到 4.5:1 对比度。大号文字至少 3:1；这里的大号是至少 24 CSS px 的常规字，或约 18.67 CSS px 的粗体。不要把 18px 常规正文按大号字放宽。
- 必要控件边界、选中标记和焦点提示，针对实际相邻颜色核对至少 3:1。纯装饰分隔线与必要操作边界有不同职责。
- 颜色同时配文字或形状提示。主要触控目标以 44px 为默认，紧凑控件保持足够命中空间与间隔。
- 使用语义标题、导航、main、表单 label 和可访问名称。长页面提供跳转主要内容入口，DOM 顺序与阅读顺序一致。
- 用键盘实际走完相关路径，检查菜单、对话框、Tabs 的进入、切换与返回；不能以“用了 Base UI”代替组合验证。
- 布局先重排再压缩。Flex / Grid 子项在需要时设置 `min-width: 0`；不以全页 `overflow-x: hidden` 掩盖溢出。
- 变化只在必要时播报，避免连续输出或静态说明反复打断阅读。减少动态效果时取消无必要过渡。

文字对比阈值依据 [WCAG 2.2：Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。实际检查需要覆盖相邻背景与组件状态，单个 token 合格不等于整页合格。

## 动效与文案

默认静止。过渡解释展开、选择、等待和完成，不增加页面入场编排、滚动揭幕、模拟打字、发光状态点或循环装饰。内容在动画未触发时仍可读。

按钮写清动作和对象，如“保存修改”“查看结果”；错误说明问题和下一步。状态区分“已保存”“执行已结束”与业务对象的完成。避免空泛宣言、过度夸奖、反复口号和不帮助用户决策的内部术语。

默认不采用渐变文字、玻璃卡片、彩色侧边粗线、装饰纹理、每节编号眉题、重复的图标卡片墙或普通元数据胶囊。真实流程可以编号，真实数据可以用连续色阶；是否使用由含义决定。
