# 组件规范

组件采用项目自有的 shadcn/ui Base UI 源码。默认外观遵循 [情绪板](mood-board.md)，优先修改共享 variant，保持成熟的交互契约。

## 按钮与文字动作

| 角色 | 外观 | 用法 |
| --- | --- | --- |
| 主按钮 | `primary` 底、`primary-foreground` 字、6px 圆角 | 当前任务最主要的动作 |
| 次按钮 | `card` 底、`foreground` 字、细轮廓 | 有明确边界的辅助动作 |
| Ghost | 透明底、次要文字，hover 时轻微底色 | 工具栏和低权重动作 |
| 文字动作 | 无容器，hover 下划线，清楚的焦点 | 查看详情、返回、次级链接 |
| 危险动作 | `destructive` 语义及明确对象 | 删除、撤销等有实际影响的动作 |

普通按钮以 14px / 500、上下 7px、左右 13px 内边距为起点，不固定高度裁剪长文案。窄屏允许换行或调整布局。触控主操作保证至少 44px 的目标高度；桌面紧凑尺寸与触控命中区分别处理。

通常一个任务区域只有一个最强动作，其他动作降低视觉权重。主按钮 hover / pressed 采用同一中性色阶的轻微变化，不切换到蓝色或绿色。次按钮若必须依靠轮廓辨认操作区域，轮廓采用满足对比要求的 `input` 角色，而不是更浅的结构分隔线。

pending 时防止重复提交，并显示“正在保存”等真实状态；不要让文案变化造成按钮跳动。disabled 仍要能解释不可用原因。图标按钮具备可访问名称，导航使用链接语义，执行动作用按钮语义。

## 输入、选择与开关

- **普通输入。** `card` 表面、`input` 边界、6px 圆角，内边距约 `10px 12px`。组合输入区或 composer 使用 10px 圆角，内边距约 16px。不要把所有输入统一成大圆角盒子。
- **标签。** 可见 label 与控件关联，placeholder 只给示例。辅助文案解释必要格式；错误紧邻字段，用 `aria-invalid` 和描述关联表达。
- **焦点。** 默认 2px `ring` 外轮廓、3px offset。必要时调整以避免裁切，不能直接移除焦点样式。
- **错误与恢复。** 保留输入，指出具体问题和修正方式。错误不能只存在于 toast 中。readonly 与 disabled 分开处理，仍需复制的只读内容保持可选取。
- **Select。** 简单选择可以用原生 select，需要搜索或复杂选择时再使用 Base UI 组合控件。保持 label、当前值和键盘操作明确。
- **Switch / Checkbox。** 各自使用开关或选择语义；checked 与 disabled 可辨认，标签区域也应方便点击。避免以普通圆点代替成熟控件。

## 导航、Tabs 与内容行

导航采用文字与必要图标，字号约 14px，条目圆角 6px、内边距约 `10px 12px`。主导航可用强选中，局部索引用 `accent` 轻选中；同时提供 `aria-current` 等恰当语义。

Tabs 表达同一上下文中的不同视图，当前项通过底色或细标记与字重区别。保留方向键导航、焦点与面板关联；切换布局时验证草稿和选中状态不会丢失。不要为了得到某种外观，把链接导航错误改成 Tabs。

列表与引用优先做成平面行：标题、必要说明、状态与去向有共同对齐关系。长标题自然换行，元数据让位于主内容。整行可点击时避免嵌套交互元素；次级动作需要独立的点击和键盘路径。

## 浮层与渐进展开

- **菜单、Popover。** 内容紧凑，默认 12px 圆角、可辨认边界与有限抬升。使用原语的 portal / 定位能力，避免被滚动容器裁切，并核对深浅主题是否正确继承。
- **Dialog / AlertDialog。** 仅在任务需要独立上下文或明确确认时使用。标题、说明和动作清楚，关闭后焦点回到合理位置；按对应原语语义处理焦点、Escape 和关闭行为。
- **Collapsible。** 摘要可读，触发展开可发现。工作过程、来源和诊断可折叠，最终结果与必要操作直接呈现。
- **层叠。** 在项目中定义菜单、固定工具栏、模态层等语义层级，避免页面各自添加 `9999`。

## 状态、反馈与空态

| 场景 | 呈现方式 | 保持的事实 |
| --- | --- | --- |
| 读取中 | 已知布局用 skeleton；小型局部动作可用进度提示 | 不能伪造内容或完成百分比 |
| 首次使用 | 一句处境说明与可开始的动作 | 不让用户先学习整套方法论 |
| 无筛选结果 | 显示当前条件与清除入口 | 与真正没有数据的空态区分 |
| 处理完毕 | 说明当前事项已处理 | 不暗示不相关业务也已完成 |
| 保存中 / 已保存 | 状态靠近编辑对象 | 区分本地草稿与服务端确认 |
| 失败 / 冲突 | 就近说明、保留输入、提供实际恢复路径 | 不静默覆盖内容或假装成功 |

状态有文字，可配统一的线性图标。普通时间、数量和说明使用文本；badge 只用于值得快速辨认的分类或状态，不给所有元数据套胶囊。

## 图标、表格与长内容

Lucide 保持同一套线性风格，沿用 24px viewBox；按控件缩放显示，线重以约 1.65px 为视觉起点。图标不能比动作文字更抢眼，也不需要彩色底块。

数据表使用语义 table；文字列左对齐，数字及对应表头右对齐，单位和精度保持一致。表格宽度服务于查找任务，窄屏先重排或简化，必要时局部滚动。不要缩小正文或裁掉表头来保住桌面构图。

组件完成后验证实际相关状态：键盘焦点、禁用、等待、错误、长标签、窄屏和已有主题。原语提供基础能力，最终组合仍由项目负责。
