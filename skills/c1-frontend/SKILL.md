# C1 前端工程与产品气质

> 草稿 · 2026-09-10

默认做简单、易用、克制、精确的产品。用户打开界面就能看清当前内容、真实状态和下一步动作；长时间使用仍然舒适。视觉品质来自排版、对齐、层级和反馈的准确性。

这份 Skill 同时约定工程底座和默认 taste。技术底座承载可靠交互，情绪板决定颜色、字体、密度和形状，页面结构由用户任务决定。

## 使用边界

- 用户对当前任务的明确要求优先，其次是项目已确认的产品说明、设计系统和组件约定，再使用本 Skill 的默认值。外部参考用于补充判断。
- 新项目采用下述技术架构和情绪板。已有项目先检查框架、token 和组件；局部修改沿用现状，不因加载 Skill 自动迁移技术栈或重做品牌。
- 用户已给出清楚的方向就直接落实。只有缺失信息会实质改变页面任务、品牌或行为时才澄清。

## 前端工程默认值

| 层级       | 默认选择                             | 职责                                    |
| ---------- | ------------------------------------ | --------------------------------------- |
| 应用       | React + TypeScript + Vite            | 组件、类型、开发与构建                  |
| 样式       | Tailwind CSS 4 + `@tailwindcss/vite` | 布局、响应式、状态样式和语义 token 映射 |
| 基础组件   | shadcn/ui 的 **Base UI 版本**        | 项目拥有源码，集中维护外观、尺寸和变体  |
| 交互原语   | `@base-ui/react`                     | 复杂控件的组合、键盘与焦点行为          |
| 变体与图标 | CVA、`cn`、Lucide React              | 一致的变体、类名组合与线性图标          |
| 产品表达   | 语义 CSS 变量、Geist / Geist Mono    | 配色、字体、密度、圆角和层次            |

版本按项目兼容性和锁文件确定。shadcn 提供组件源码，Base UI 提供底层交互，它们都不替代产品设计。简单控件可以使用原生元素。

先复用现有组件，再增加必要的 variant。共享外观进入基础组件，页面组合留在业务组件，业务状态与请求规则保持独立。

新增项目、组件或主题时阅读 [架构与维护边界](references/architecture.md)。

## 默认感觉与外观

**克制、清醒、可信、专注、连续。**

- **矿物白与石墨色。** 主工作面浅色为 `#FBFBF9`，文字为 `#22241F`；深色分别为 `#20221E`、`#EDEEE8`。略带绿灰的中性色形成安静的层次，石墨色承担主操作。
- **颜色解释意义。** 蓝色提示信息与焦点，绿色表示已确认的成功，琥珀色提示待判断，红色表示失败或危险。普通选中、业务完成和保存成功各自有清楚的含义。
- **控件紧凑，正文舒展。** 默认 UI 为 14px，正文 15px / 1.8，页面标题 28px / 600。Geist 承担日常阅读，Mono 只用于代码、时间戳和精确标识。
- **连续的内容表面。** 先用共同边界、留白和细分隔组织内容。容器用于输入、交互分组和浮层，避免把每段内容都装进卡片。
- **有角色差异的几何。** 普通控件圆角 6px，组合输入区 10px，浮层默认 12px。常规内容保持平面，阴影只在需要区分浮层时使用。
- **默认静止。** 状态过渡以 160ms 为起点，动效解释变化、保持连续性；减少动态效果时，内容和操作依然完整。

实施视觉前阅读 [配色情绪板与排版](references/mood-board.md)。这些是可替换的默认值；新品牌可以改变表达，但仍需保持语义、可读性和一致性。

## 设计判断

1. **主任务先于外壳。** 首屏露出真正要阅读、操作或判断的对象。工作工具不让用户先穿过宣传段落。
2. **层级来自关系。** 同级内容采用一致的排版和基线；相关内容靠近，段落转折留出更大间距。每个间距只有一个所有者。
3. **熟悉的交互建立信任。** 导航、表单、Tabs 和弹窗采用成熟模式。组件有一致的外观，也有完整的焦点、错误和等待反馈。
4. **真实状态比漂亮状态更重要。** 未保存、执行结束和业务完成不能混为一谈。失败保留用户输入，并说明可做的下一步。
5. **适配不同屏幕。** 窄屏下调整布局，保留主要内容和操作入口。切换视图或主题时，保留用户输入、选中项和阅读位置。

编写或修改控件时阅读 [组件规范](references/components.md)。

## 工作方式

1. **看现状。** 读相关产品说明、token、现有组件和当前页面。明确用户的主任务、主要动作和需要保持的状态。
2. **定表达。** 复用已确认的情绪板；没有品牌要求时使用本 Skill 默认值。先安排内容层级、组件关系和窄屏组织，再调整局部外观。
3. **做相关状态。** 按组件需要覆盖 default、hover、focus、pressed、disabled、pending，以及页面的 loading、empty、error、success。保存与冲突等状态只在实际业务涉及时补齐。
4. **检查真实组合。** 运行相关的类型、构建和行为检查；在浏览器查看桌面、窄屏、相关主题、键盘路径、长内容及焦点。主题变化核对 portal 中的浮层。
5. **说明结果。** 简短说明改动、实际验证与尚未验证的边界。截图证明外观；真实保存、执行和恢复需要对应业务链路证据。

不要用通用检查表代替用户要求的交付。对局部修改按影响验证；对新页面验证主要使用路径。
